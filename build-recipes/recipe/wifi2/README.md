# wifi2: исправления устойчивости и отдельная сборка Full LTO

Актуальный статус сборки находится в `STATUS.json`; итоговые результаты — в
`artifacts/realme-note60x/wifi2-reviewed/` после завершения всех проверок.
Прежние `gki-wifi1`, `wifi1-reviewed` и ZIP не содержат этих исправлений.

В источниках RTL8812AU добавлены проверки размера radiotap относительно
256-байтового локального буфера и размера 802.11-кадра относительно доступного
буфера передачи. Эти проверки выполняются до копирования данных.

В RTL8188EUS добавлены проверки минимального размера radiotap и диапазона
размера кадра; цикл пропуска radiotap заменён на пропуск без временного буфера.
Состояние читателя пакета инициализируется до возможного раннего выхода.
Это устраняет обнаруженные риски выхода за границы и некорректного цикла.
Поддерживаемые этим путём кадры должны иметь как минимум 24-байтовый заголовок;
RTL8812AU отклоняет radiotap длиннее своего 256-байтового буфера.

Linux-прототипы `rtw_xmit_entry` в RTL8188EUS и RTL8812BU приведены к возврату
`netdev_tx_t`, ожидаемому `ndo_start_xmit`. Старый возврат `int` даёт другую
идентичность Clang CFI. `test_xmit_cfi.py` проверяет типы TX-обработчиков всех
трёх Realtek-драйверов Clang 14 относительно настоящего заголовка ядра и
использует старый `int` как отрицательный контроль. Это проверка конкретных
деклараций, не всех обработчиков или выполнения CFI на устройстве.
`audit_compiled_xmit_cfi.py` затем проверяет строковые и числовые CFI-типы
в настоящих LLVM-объектах всех трёх TX-обработчиков до компоновки модулей.

`monitor-tx-bounds.patch` показывает изменения относительно сохранённой wifi1.
Полные изменённые файлы находятся в `sources/`, лицензии сохранены в исходниках
и базовом архиве. RTL8812BU/RTL8822BU, MT7612U и AR9271 остаются в сборке.
Исправление проверок длины не доказывает устранение всех ошибок драйверов.

`full-lto.config` отличается от конфигурации wifi1 только переключением
Thin LTO → Full LTO, как в штатной конфигурации. CFI, MODVERSIONS, BTF,
защита подписи модулей и все прежние драйверы сохранены. Режим LTO сам по себе
не объясняет неподтверждённую загрузку wifi1 и не даёт гарантии загрузки wifi2.
OEM-подпись у новой сборки от этих изменений не появится.

`test_monitor_bounds.py` извлекает исправленные участки обработки из исходников
и создаёт C-проверку граничных случаев. Она проверяет 128 случаев
для четырёх размеров дескриптора с AddressSanitizer/UndefinedBehaviorSanitizer.
Все 128 случаев прошли в отдельно разрешённом пользователем Linux-сеансе;
результаты находятся в `bounds-test/results.json`.
Полный драйвер этим небольшим тестом не моделируется.

`run_full_lto.py` предназначен для отдельного разрешённого Linux-сеанса:
использует прежние исходники common только как вход, извлекает копии драйверов
в `wifi2-full-lto/drivers`, собирает в `wifi2-full-lto/out`, размещает модули
в `wifi2-full-lto/stage`. Исходный `out-wifi1` не используется как выход.
Сборка идёт одним заданием с меньшим приоритетом; linker использует один поток.
Нужны минимум 18 GiB доступной RAM+swap и 15 GiB свободного места — это пороги
предварительной проверки, а не гарантия достаточности ресурсов для Full LTO.
Скрипт не меняет настройки WSL, не перезапускает его и не завершает чужие процессы.
Первый запуск Full LTO исчерпал прежние 16 GiB RAM + 4 GiB swap. По новому
прямому указанию пользователя `.wslconfig` изменён на 28 GiB RAM + 16 GiB swap,
после чего WSL перезапущен для применения лимитов. Исходный файл и описание
изменения сохранены в `wsl-resource-change/`; объекты сборки сохранены.

После компиляции ещё потребуются проверка ABI/подписей, упаковка нового boot
и нового ZIP с хешем новой конфигурации. Прежний ZIP нельзя автоматически
считать подходящим для wifi2. Автоматического развёртывания или испытаний
на телефоне в рецепте нет.

Хостовая подготовка без запуска WSL:

```powershell
python build/realme-note60x/wifi2/prepare_host.py
python build/realme-note60x/wifi2/test_monitor_bounds.py --generate-only
```

В уже разрешённом Linux-сеансе сборка вызывается с явным флагом:

```bash
python3 /mnt/f/wifi_work/build/realme-note60x/wifi2/run_full_lto.py --build
```

Если исходная сборка была начата с первым вариантом патча, до добавления
исправлений CFI, `refine_cfi_build.py` обновляет только две внешние сборки после
её завершения; хеш готового ядра при этом должен сохраниться. Новая сборка с
актуальными шестью изменёнными исходниками включает проверку CFI сразу.
Для прерванной незавершённой сборки первого варианта предусмотрен явный
`--resume-bounds-profile`: он принимает только закреплённый старый профиль,
проверяет прежние исходники и сохраняет уже собранные объекты ядра. В текущей
сборке этот путь использован после Hangup терминала на этапе компоновки.

Запуск WSL разрешён пользователем отдельно после первоначального отказа
автоматической проверки. Сам рецепт никогда не запускает и не перезапускает WSL.
`export_wifi2.py` переносит собранные файлы на ПК, общие валидаторы проверяют
ELF/ABI и подписи, `diagnostics/package_realme_wifi2.py` формирует образ AVB NONE,
а `finalize_wifi2.py` публикует итоговый отчёт и контрольные суммы.
